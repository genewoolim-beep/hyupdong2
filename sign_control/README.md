# 수어 인식 — 녹화 / 학습 / 실시간 인식

웹캠 앞에서 수어 동작을 하면 텍스트로 바꾸고, LLM이 자연스러운 문장으로 옮긴다.
로봇 제어의 입력단으로 쓰기 위한 모듈이다.

```
카메라 ─→ 랜드마크 추출 ─→ 특징 벡터 ─→ 구간 분할 ─→ 분류 ─→ 문법 보정 ─→ LLM
 30fps      MediaPipe        104차원      손 유무      GRU      명사+동사    문장
```

**사전학습 모델은 없다.** 직접 녹화한 동작만 인식한다.
수어판 Whisper 같은 것은 존재하지 않으며, 한국수어는 특히 그렇다.
대신 어휘를 좁히면 개인화 모델이 매우 정확해진다.

---

## 결과

| 항목 | 값 |
|---|---|
| 학습 어휘 | 20개 — 색 6(빨강·주황·노랑·초록·파랑·보라) · 구역 6(1~6번구역) · 물체 2(나사·망치) · 동작 6(가져오다·놓다·들다·똑같이·조립하다·좌우대칭) |
| 샘플 수 | 라벨당 20개, 총 400개 |
| 검증 정확도 | **100%** (혼동쌍 0, 약한 라벨 0) |
| 학습 시간 | 55초 (RTX 3070, 1,200샘플 기준 환산) |
| 추론 시간 | 0.5 ms |
| 실행 프레임률 | 30 fps |
| 인식 지연 | 손 내린 뒤 167 ms |

정확도 아래 항목들은 어휘 7개(청소하다·정리하다·물건·컵 …)로 처음 측정한 값이다.
의미가 가까운 `청소하다`↔`정리하다`, `물건`↔`컵` 도 혼동 없이 분리되었다.
어휘를 20개로 늘린 뒤로는 다시 재지 않았다 — `python3 sign_demo.py train` 이
학습 끝에 출력하는 값으로 갱신할 것.

## 설치

```bash
git clone https://github.com/genewoolim-beep/hyupdong2.git
cd hyupdong2
pip install -r requirements.txt
cd sign_control
```

> `mediapipe` 1.x 는 numpy 2.x 를 끌어와 `cv_bridge` 와 충돌한다.
> ROS2 와 같은 환경에서 쓸 계획이면 `numpy==1.26.4` 를 유지할 것.
> 또한 0.10.35 부터 legacy `mp.solutions` API 가 제거되어 tasks API 를 쓴다.

### MediaPipe 모델 내려받기

용량이 커서 저장소에 포함하지 않았다. **`sign_demo.py` 와 같은 폴더**에 받는다.

```bash
cd sign_control

wget https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task
```

### 경로·카메라 설정

모든 경로는 스크립트 위치를 기준으로 잡히므로 clone 후 바로 실행된다.
다른 곳에 두었다면 환경변수로 덮어쓴다.

| 변수 | 기본값 | 용도 |
|---|---|---|
| `SIGN_MODELS` | `sign_demo.py` 가 있는 폴더 | `.task` 파일 위치 |
| `SIGN_DATA` | `./sign_data` | 녹화 데이터 위치 |
| `SIGN_CAM` | `1` | 카메라 인덱스 |

```bash
SIGN_CAM=0 SIGN_MODELS=~/models python3 sign_demo.py run
```

`ls /dev/video*` 로 카메라 번호를 확인할 수 있다.

## 사용법

```bash
python3 sign_demo.py record 청소하다 -b 20   # 샘플 20개 연속 녹화
python3 sign_demo.py list                    # 수집 현황
python3 sign_demo.py train                   # 학습 + 혼동 리포트
python3 sign_demo.py run                     # 실시간 인식
python3 sign_demo.py run --llm               # + GPT 문장 변환
```

`--llm` 은 환경변수 `OPENAI_API_KEY` 를 읽는다.

### 조작

| 모드 | 키 |
|---|---|
| record | `SPACE` 녹화 · `U` 마지막 삭제 · `ESC` 배치 중단 · `Q` 종료 |
| run | `C` 문장 지우기 · `ENTER` LLM 통역 · `Q` 종료 |

`run` 화면 하단에 **[지우기] [통역]** 버튼도 있다.

## 어떻게 만드는가

### 1. 어휘를 고른다

[국립국어원 한국수어사전](https://sldict.korean.go.kr/) 에서 검색한다.
약 12,500단어에 영상·손모양 사진·동작 설명이 있고, **손모양으로 역검색**도 된다.

역검색으로 이미 고른 단어와 손모양이 겹치는 것을 피하면 혼동을 미리 줄일 수 있다.

### 2. 녹화한다

> **모델은 '옳은 수어'가 아니라 '당신이 일관되게 하는 동작'을 학습한다.**

| | 결과 |
|---|---|
| 조금 틀리지만 매번 똑같이 | 95% 인식 |
| 정확하지만 할 때마다 다르게 | 실패 |

정확도보다 **일관성**이 중요하다. 라벨당 20개 최소, 40개 권장.
녹화 중에는 자리를 옮기지 말 것.

### 3. 학습하고 리포트를 읽는다

```
혼동된 쌍 (실제 → 오인):
  거실 → 주방   1회
약한 라벨:
  거실               75%
```

30개 중 무엇을 고쳐야 하는지 알려준다. 뜬 단어만 추가 녹화하면 된다.
같은 명령을 다시 실행하면 기존 파일에 덧붙는다.

## 설계 요점

### 특징 — 손의 위치와 모양을 분리한다

```python
(H[0] - origin) / scale        # 손목이 몸의 어디에 → 위치
((H - H[0]) / span).ravel()    # 손 자체가 어떤 모양 → 손모양
```

수어의 음운은 **손모양 · 위치 · 움직임** 으로 구성된다. 특징 공간을 그 구조에
맞췄다. 랜드마크를 그냥 일렬로 펴는 것보다 학습이 훨씬 안정적이다.
움직임은 시간 축이 담당한다.

### 정규화 — 어깨 중점 원점, 어깨너비 단위

| 조건 변화 | 특징 벡터 |
|---|---|
| 화면 좌/우 이동 | 동일 |
| 카메라와의 거리 | 동일 |
| 앉기 / 서기 | 동일 |
| 해상도 640 → 1280 | 동일 |

마지막 줄 덕분에 **카메라를 바꿔도 재학습이 필요 없다.**

### 인식 단위 — 슬라이딩 창이 아니라 '구간'

```
손 없음 ─── 손 올라옴 ──────── 손 내려감 ─── 5프레임 대기 ─── 분류
   대기     ↑구간 시작                        ↓
           앞 6프레임도 포함                  여기서 한 번만 분류
```

학습 데이터가 `한 클립 = 한 동작` 이므로 인식도 같은 단위여야 한다.

> 슬라이딩 창으로 하면 `가져오다` 처럼 **손을 내리며 끝나는 동작**이 원리적으로
> 확정되지 않는다. 확률이 100% 가 되는 그 순간 손이 이미 사라져 있기 때문이다.
> 실제로 이 버그를 겪고 재설계했다.

### 문법 사전지식 주입

```python
if 직전이 명사:
    p[동사들] += 0.05      # 곱셈이 아니라 덧셈
```

`×1.05` 로 하면 재정규화가 상승분을 도로 깎아 `0.89 → 0.893`, 사실상 무효다.
정작 필요한 경계 구간에서 효과가 없어 덧셈으로 바꿨다.

```
컵 → 가져오다 76%  →  81%  통과
컵 → 애매    45%  →  50%  거부
```

명사 뒤에 동사가 붙은 짝은 화면에 **파란색**으로 표시된다.

## 모델

```
입력 (32, 104)
  ↓ 양방향 GRU 2층, 은닉 128
  ↓ 평균 풀링 + 최대 풀링 이어붙이기   ← 전체 흐름 + 결정적 순간
  ↓ FC 512 → 128 → N
출력 N개 확률
```

542,469 파라미터.

**증강** — 데이터가 적으니 필수다.

| 종류 | 범위 | 흡수하는 것 |
|---|---|---|
| 크기 | ±8% | 몸 크기 차이 |
| 잡음 | σ=0.012 | 랜드마크 떨림 |
| 시간 왜곡 | 0.8~1.25배 | 동작 속도 차이 |

## 조절 상수

`sign_demo.py` 상단에 있다.

```python
CONF_TH    = 0.80    # 확정 임계값. 오인식이 잦으면 올린다

```

## 성능 내역

```
카메라       33.3 ms
MediaPipe    22.4 ms   해상도와 무관 (내부에서 리사이즈)
화면 그리기   7.3 ms
분류          0.5 ms
────────────────────
             ~30 ms → 30 fps
```

두 가지가 크게 잡아먹고 있었다.

| 문제 | 조치 | 효과 |
|---|---|---|
| PIL 텍스트 왕복이 프레임당 7회 | 한 번에 일괄 렌더 | 36 → 9 ms |
| C270이 저조도에서 스스로 15fps로 떨굼 | `exposure_dynamic_framerate=0` | 15 → 30 fps, 밝기 손해 0 |

두 번째는 `open_cam()` 에서 `v4l2-ctl` 로 자동 설정한다.
해상도를 낮추는 것은 **효과가 없다** — MediaPipe 비용이 해상도와 무관하기 때문이다.

## 한계

**화자 의존**
이 모델은 녹화한 사람 1인에게 최적화되어 있다. 다른 사람은 잘 인식되지 않는다.
공개 벤치마크에서도 화자독립 조건은 화자의존 대비 15~25%p 떨어진다.

역으로, 개인용으로는 [AI Hub 53만 영상](https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=636)
으로 학습한 모델보다 **직접 녹화한 20개가 더 정확하다.**

**수어 전문성**
사전 영상을 보고 따라 한 것은 근사치다. 실제 농인 사용자의 수어와는 다르다.
본 구현은 **기술 타당성 검증**이며, 접근성 제품이 되려면 다화자 데이터와
농인 사용자 참여 검증이 필요하다.

**연속 수어 미지원**
동작 사이에 손을 내려 구분해야 한다. 쉼 없이 이어지는 실제 수어는 다루지 못한다.

**현재 모델은 움직임을 거의 쓰지 않는다**

측정 결과다.

```
원본                        100.0%
시간 뒤집기                  100.0%     ← 거꾸로 해도 같은 답
시간 순서 섞기                99.3%     ← 프레임을 뒤죽박죽해도 같은 답
평균 한 프레임을 32번 반복      90.7%     ← 움직임을 없애도 맞힘
(순수 잡음 입력은 11.4% — 검사 자체는 정상)
```

현재 7개 단어가 **손의 자세만으로 이미 구분되기 때문**이다. 학습이 굳이
어려운 길인 시간 패턴을 배울 이유가 없었다. 클래스 평균 자세 사이의 최소
거리가 2.29 로 충분히 벌어져 있다.

당장은 문제가 없지만, **손모양·위치가 같고 움직임만 다른 단어 쌍**이
들어오면 구분하지 못한다. 어휘를 30개 수준으로 늘리면 이런 쌍이 생긴다.
실제 수어에는 방향이나 반복 횟수로만 갈리는 단어가 흔하다.

혼동 리포트에 특정 쌍이 계속 뜨는데 동작이 분명히 다르다면 이 원인을 의심한다.
확인은 위와 같이 시간을 뒤집어 보면 된다.

대응 방향은 셋이다. 3번이 가장 확실하며 특징 차원이 104 → 208 로 느는 정도의 비용이다.

1. 속도 증강을 더 크게 (0.8~1.25배 → 0.5~2.0배)
2. 프레임을 섞은 것을 오답으로 학습시키기
3. 프레임 간 차분을 특징에 추가해 움직임을 직접 보게 하기
